Security Disclosure & Compliance

Last updated: October 2026

1. Vulnerability Reporting & Security Disclosure

I take the security of the LDLx sovereign architecture seriously. Because our systems are engineered for high-assurance, air-gapped, and mission-critical enterprise environments, I encourage responsible disclosure of any potential vulnerabilities discovered by security researchers or users.

If you identify a security issue or cryptographic weakness within the core Debian kiosk pipeline, `DbServerManager` API, or Flutter binaries, please report it directly through my secure repository channels. I commit to prompt investigation and rapid patch deployment for verified anomalies.

2. Compliance Statement

LDLx is built to facilitate rigorous compliance standards for corporate clients operating in regulated sectors, including defense, finance, and secure infrastructure:

  • Zero Telemetry Compliance: Because the OS runs fully self-contained without background cloud logging or unverified telemetry daemons, organizations maintain strict data residency control.
  • Air-Gapped Readiness: Designed to function entirely offline without dependencies on external SaaS verification loops.
  • Open Source Auditability: Fully inspectable codebase under the GPL-3.0 License, enabling internal security teams to verify every line of execution before hardware deployment.

3. Hardware & Operational Boundaries

While LDLx provides an immutable, hardware-isolated base layer via systemd and secure local database management, endpoint security relies heavily on physical hardware integrity, BIOS/UEFI password protection, and secure storage encryption implemented by the deploying organization.
